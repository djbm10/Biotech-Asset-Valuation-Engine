# Authority assertion provenance sidecar v1 schema

This is an additive, offline artifact. Legacy authority lookup, snapshot contents and
parser decisions do not consume it. The capture API accepts raw mappings, preserves
origins, and returns a separate ledger; it does not overwrite a SourceEntityRecord.

## assertions.jsonl.gz

Each canonical JSON row is one raw assertion origin, before normalized deduplication.

| Field | Meaning |
|---|---|
| schema | authority_assertion_provenance_v1 |
| assertion_id | SHA256 of canonical JSON source identity fields below |
| source / release | Original authority and pinned release |
| artifact_sha256 / artifact_path | Actual frozen artifact hash and relative bundle path |
| row_index / record_id | Zero-based row in that artifact and its upstream record ID |
| field_path | Exact mixed string/index path to the raw scalar |
| upstream_component | ChEMBL component index/accession, or null when the authority asserts the field at record level |
| component_interval | Zero-based half-open offsets into raw_scalar |
| raw_scalar / raw_component | Unmodified scalar and exact selected substring |
| assertion_type | SYMBOL, APPROVED_NAME, SYNONYM or source-derived XREF |
| snapshot_role | canonical_symbol, label, alias, or alias_and_symbol |
| transforms | Ordered operation objects with exact input/output and slice parameters |
| normalized_key | Result of replaying the recorded operations |
| snapshot_records_sha256 | Binds linkage to the immutable accepted snapshot |
| source_record_key / snapshot_fields | Exact existing snapshot record and all output fields it produced |
| resolver_components | All source-record components for that record, distinct from canonical IDs |

Assertion ID includes source/release, artifact SHA256, record ID, row index, field path,
component interval, raw component and upstream component. It excludes timestamps,
matching key, canonical ID and runtime process order. Relative path is explanatory,
not an identity substitute for the content hash.

A resolver component contains component_id, sorted record_keys, canonical_id and
canonical_label. Its ID hashes the snapshot digest and sorted record keys. Shared
canonical_id does not merge components. canonical_label is the existing component's
label, not a label recovered by an ambiguous get(canonical_id) operation.

Transform names are slice, strip, whitespace_collapse, casefold, lookup_separators.
lookup_separators applies only the existing '-'/'_'/'/' to-space rule. No Unicode
normalization, Greek transliteration, new case rule or fuzzy lookup was added. Each
input and output is retained, including no-op operations in the real matching path.
ChEMBL scalar payload/split selection is represented by its exact slice interval;
raw_scalar still contains the discarded prefix and delimiters. Actual historical
ChEMBL rows are unavailable; that adapter's component behavior is validated only by
frozen synthetic controls, not presented as recovered source evidence.

## linkage.jsonl.gz / unrecoverable.jsonl.gz

One row per existing nonempty canonical symbol, label or stored alias value field.
record_key + field + snapshot_records_sha256 is the locator. value is explicitly the
snapshot value, never relabelled original upstream text. RECOVERABLE rows list every
assertion_id producing that field; several origins can share one output. UNRECOVERABLE
rows have an empty list and ORIGINAL_INGESTION_ARTIFACT_UNAVAILABLE. No synthetic raw
assertion is emitted. The unrecoverable file is the exact subset of linkage rows with
that status. Cross-reference join evidence remains the existing resolver's responsibility;
this sidecar preserves target name/assertion origins and observes its canonical linkage.

## Auxiliary artifacts

- raw_artifacts.json pins source SHA256, original path, size and row count.
- query_linkage_audit.json covers all 124 cases and 443 assertion occurrences.
- collision_report.json preserves normalized keys with >1 exact raw substring and
  canonical IDs with >1 existing resolver component. Counts do not alter decisions.
- counts.json distinguishes raw origins, snapshot fields, records and canonical IDs.
- manifest.json binds generated bytes. gzip uses mtime=0 and an empty filename header.

The generator refuses parsed-record drift, missing linkage for any available raw
assertion, duplicate raw IDs, or missing Open Targets records. Accepted snapshot hashes
are checked before and after materialization. It does not fetch sources or update the
accepted snapshot. Future ingestion must explicitly adopt capture before discarding raw
payloads; merely installing this standalone module does not change the legacy builder.
